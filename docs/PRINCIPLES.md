# Principles

These principles guide future Aether features. They should shape product decisions, interface copy, technical architecture, and Nova's behavior over time.

1. Local-first whenever practical.

   Aether should prefer local data, local models, and local control when they can serve the user's needs well.

2. The user stays in control.

   Nova can suggest, explain, and assist, but the user should make meaningful decisions.

3. Privacy before convenience.

   Aether should not trade user privacy for ease unless the user clearly understands and chooses that tradeoff.

4. Simplicity over unnecessary complexity.

   Features should solve real problems without adding avoidable setup, clutter, or hidden behavior.

5. Features should feel integrated rather than bolted on.

   New capabilities should fit Aether's existing flow, visual style, and architecture.

6. Nova assists without becoming intrusive.

   Nova should help at the right moment, then get out of the way.

7. Reliability is more important than novelty.

   A feature that works predictably is more valuable than one that feels impressive but fragile.

8. Clear communication beats clever wording.

   Aether should say what is happening, what changed, and what the user can do next.

9. Errors should be visible and recoverable.

   Failure states should be calm, honest, and actionable.

10. Placeholders should be clearly marked.

    If a feature is not active yet, Aether should not imply that it is.
